# 개발 문서

작성 기준: 2026-11-17. 기능·실행은 [README](../README.md), 배포는 [배포 문서](deployment.md)를 참고하세요. 이 문서는 현재 코드 구조, 데이터 연결, 구현 규칙과 남은 작업을 관리합니다.

## 1. 코드 구조

| 구성 | SpecSignal 작업 폴더 | PLSAi 실행 저장소 |
|---|---|---|
| 화면 | `src/web/index.html` | `index.html` |
| 스타일 | `src/web/CSS/style.css` | `CSS/style.css` |
| 프론트엔드 | `src/web/js/app.js`, `backend.js`, `academic.js` | `js/`의 같은 파일 |
| 서버 | `src/web/server.py` | 같은 경로. 정적 파일 루트만 다름 |
| 인증 | `src/web/auth.py` | 동일 |
| 학교 일정 | `src/academic/discovery.py`, `routes.py` | 동일 |
| DB 연결 | `src/db/connection.py` | 동일 |
| 공식 API | `src/certification/collect_items.py`, `collect_info.py`, `normalize.py` | 동일 |

`app.js`는 기본 화면·일정, `backend.js`는 실제 자격증·공모전과 일정 기본 날짜, `academic.js`는 로그인·프로필·학교 일정 동기화를 담당합니다. 로딩 순서는 `app.js` → `backend.js` → `academic.js`입니다.

PLSAi는 루트 `index.html`, `CSS/`, `js/`를 유지합니다. `pages/`와 기존 Markdown은 변경하지 않습니다. 실제 `.env`, 테스트, 개발 산출물은 실행 코드 업로드 대상이 아닙니다.

### 계정·프로필

회원가입과 로그인은 별도 화면이며 텍스트 링크로 전환합니다. 회원가입에는 비밀번호 확인이 있습니다. 이메일 확인이 필요하면 인증 링크 확인 후 로그인합니다. Supabase Authentication의 사용자 생성 트리거가 `profiles`·`user_preferences`를 만듭니다. 프로필 테이블에 행만 직접 넣어서는 로그인할 수 없습니다.

로그인 화면에는 프로필 입력란을 숨깁니다. 서버에 학교·학과가 있으면 홈으로 이동하며, 없을 때만 최초 입력을 받습니다. 이름은 선택 항목입니다. 프로필은 AI 검색과 독립적으로 저장하고 마이페이지에서 수정합니다. 공부시간·준비기간·캠퍼스의 계정 간 저장·복원은 아직 완성하지 않았습니다.

토큰은 sessionStorage에 저장하고 서버가 서명·발급자·만료·역할을 검증합니다. 비대칭 키는 공개 JWKS, 레거시 HS256은 `SUPABASE_JWT_SECRET`을 사용합니다. 자동 세션 갱신은 미구현입니다.

가입 실패의 `over_email_send_rate_limit`(HTTP 429)은 Supabase 인증 메일 한도 문제입니다. SMTP·이메일 인증 설정을 확인해야 합니다. 오류 응답의 숫자 `code`보다 실제 사유인 `error_code`를 먼저 판독합니다. 개발 테스트는 Authentication에서 Auto Confirm 사용자를 생성할 수 있습니다.

### 자격증

2026-11-10부터 현재 화면은 DB 사전 수집 대신 공식 API를 직접 조회합니다. `DATA_GO_KR_API_KEY`는 서버에서만 사용합니다. 정상 응답은 5분, 최대 256개 요청 조합을 메모리에 캐시하며 서버 재시작 시 초기화합니다. 실패와 정상 빈 결과는 구분합니다.

종목코드는 문자열을 유지하고 자격구분 코드를 일정 요청에 전달합니다. 필기·실기 접수기간·시험기간·발표일을 표시하며 미제공 날짜는 만들지 않습니다. 기존 수집 함수의 원문 저장·응답 검증·재시도를 재사용합니다.

자격구분·직무분야 필터, 검색, 카드 1열/2열, 상세 SVG 화살표와 관심 저장을 제공합니다. 카드 이름 아래 작은 관심 저장 버튼을 두고 보조 설명은 제거했습니다.

### 공모전

운영자가 추가한 `public.contests`를 서버 DB 연결로 읽습니다. 확인 당시 37건이었으며, 실제 화면은 조회 결과를 사용합니다.

| 필드 | 용도 |
|---|---|
| `id`, `title` | 식별·제목 |
| `organizer`, `categories`, `status` | 주최기관·분야 배열·상태 |
| `start_date`, `end_date` | 접수 기간·마감일 |
| `description`, `eligibility`, `prizes` | 본문·참가 조건·시상 |
| `source_url`, `image_url` | 공고 원문·포스터 |
| `created_at` | 홈 최신 등록순 |

API는 명시한 공개 필드만 반환하며 마감일 오름차순·ID 순으로 최대 1,000건을 제공합니다. 별도 페이지네이션은 없습니다. `categories` 각 값으로 필터링하고 빈 분야는 ‘기타’로 분류합니다. 검색은 제목·분야·주최기관·설명을 대상으로 합니다.

포스터는 카드·상세에 표시하고 없거나 로딩 실패하면 숨깁니다. URL은 HTTP(S)만 허용하며 서버 CSP에 외부 이미지 로딩을 허용했습니다. 원본 서버의 외부 접근 제한이나 HTTPS 페이지의 HTTP 이미지 차단은 별도 조건입니다.

## 3. 학교 시험 일정과 권한

### 조회·등록

1. 학교 공식 명칭·학과·캠퍼스·학년도로 요청합니다. 같은 학교·캠퍼스·학년도의 공유 DB 결과를 먼저 사용합니다. 공백은 정규화하지만 학교 별칭은 자동 병합하지 않습니다.
2. 캐시가 없으면 Claude 웹 검색·페이지 가져오기로 공식 `.ac.kr` 자료를 찾습니다. 학과·개인정보는 검색 요청에 보내지 않습니다.
3. 학교·캠퍼스·학년도·날짜·출처 URL·원문 근거를 검증하고 **중간고사(`MIDTERM`)·기말고사(`FINAL`)만** 제공합니다. 개강·종강·방학·수강신청 등은 제외합니다.
4. 사용자가 출처를 검토하고 선택한 항목에 ‘확인한 일정만 등록’을 눌러 개인 일정으로 저장합니다. 조회만으로 등록하지 않습니다.
5. 같은 원본의 재등록은 중복 생성하지 않고 기존 개인 수정 내용을 보존합니다. 다른 계정에는 별도 스냅샷으로 저장합니다.

기존 캐시에도 같은 시험 필터를 적용하며 표시·등록 후보의 인덱스를 일치시킵니다. 시험이 없으면 다른 행사를 대신 제공하지 않습니다. 원본은 자동 갱신하지 않으므로 공고 변경 시 운영자 재검토가 필요합니다.

### DB·접근 권한

| 테이블 | 역할 |
|---|---|
| `profiles`, `user_preferences` | 계정별 기본 정보·설정 |
| `academic_calendar_lookups` | 학교별 공유 검색 상태·후보. 브라우저 직접 접근 차단 |
| `universities`, `academic_events` | 학교·공유 원본. AI 결과는 `unverified` 유지 |
| `calendar_events` | 사용자별 일정 스냅샷. `academic_event_id`로 원본 연결 |
| `contests` | 현행 공모전 조회 원본 |

사용자 데이터는 검증된 JWT claims로 `user_transaction`의 `SET LOCAL ROLE authenticated`와 RLS를 적용합니다. `service_transaction`은 서버 내부 조회에만 사용하며 DB 접속 정보를 브라우저에 노출하지 않습니다.

미검증 공유 원본은 일반 사용자가 직접 읽을 수 없습니다. 개인 일정 조회를 원본과 사용자 권한으로 JOIN하면 저장된 일정도 누락됩니다. 이를 방지하려고 **본인 RLS로 개인 행을 먼저 읽고, 서버 내부 권한으로 그 원본 ID들의 시험 유형만 확인해 필터링**합니다. 공유 원본의 공개 권한은 넓히지 않습니다.

개인 수정·삭제는 원본이나 다른 계정에 영향을 주지 않습니다. 사용자 등록만으로 공유 원본을 검증 완료 상태로 승격하지 않습니다. 최초 요청자가 탈퇴해도 공통 캐시는 유지합니다.

학교 공통 기간과 강의별 실제 시험일은 다를 수 있습니다. 접근 제한·이미지 PDF·근거 미확인 자료는 자동 등록하지 않습니다. 작업은 웹 프로세스에서 실행하며 독립 복구 워커는 없습니다. 같은 학교의 동시 최초 요청은 DB 잠금으로 중복 호출을 막고 신규 검색은 사용자당 1분 간격으로 제한합니다. 20분 이상 중단된 작업은 재요청 시 재시작할 수 있습니다.

### 스키마 관리

기본 스키마·권한·Storage SQL은 `supabase/migrations/20261013000*.sql`, 학교 검색 캐시는 `20261115000100_academic_discovery.sql`·`20261115000200_preserve_shared_academic_cache.sql`에 있습니다. 적용 전 dry-run을 확인하고 실제 DB 변경은 별도로 진행합니다.

`contests`는 직접 추가된 테이블로 현재 마이그레이션에 생성 SQL이 없습니다. 새 DB 구축 시 별도로 준비해야 합니다. 실행 파일만 반영한 PLSAi 저장소는 기존 Supabase 프로젝트 연결을 전제로 합니다.

기존 `certifications`·상세·시험·수집상태 테이블과 `src.certification.sync` CLI, `/api/v1/certifications`는 SpecSignal에 보존하지만 현행 자격증 화면은 사용하지 않습니다. 제출·검수용 `competitions`·Storage·채팅·DB 관심 목록 설계도 현재 연결 기능과 구분합니다. 상세 제약·API 매핑·수집 정책은 [기존 DB 설계 참고](history/database-schema-reference.md)에 보존했습니다.

## 4. 홈·일정 화면 규칙

- 홈 ‘이런 도전은 어때요?’는 구간 제목 없이 6개 카드, 2열 × 3행입니다.
- 추천 자격증 3개는 정보처리기사·산업안전기사·전기기사를 우선하고 없으면 실제 목록으로 보충합니다. 인기 통계가 아니므로 ‘인기’로 표시하지 않습니다.
- 공모전 3개는 `created_at` 최신순, 동률·미제공 시 ID 내림차순입니다. 마감 여부로 제외하지는 않습니다.
- 홈 `+`는 하단 페이지 선택바 바로 위에 고정합니다.
- 자격증 일정 추가는 올해 공식 `docExamStartDt`·`pracExamStartDt` 중 오늘 이후 가장 가까운 시작일이 기본값입니다. 없으면 내년을 조회합니다. 회차·필기·실기 선택과 직접 변경을 허용합니다.
- 공모전 일정은 `end_date`가 기본값입니다. 날짜 미제공·조회 실패 시 직접 입력을 안내합니다. 비동기 응답은 사용자가 이미 수정한 날짜를 덮어쓰지 않습니다.
- 시험 시작일 기본값은 응시자격·필기 합격 여부를 판단한 결과가 아닙니다. 기간 공고라면 본인의 실제 응시일을 별도 확인해야 합니다.
- 하루 일정은 점, 기간 일정은 이어진 반투명 형광펜 띠입니다. 주·월 경계에서 나누고 양끝은 둥글게 표시하며 겹치는 일정은 별도 줄을 사용합니다.
- 홈 전체·이번 달·마이페이지 집계에 학사일정을 포함합니다. 다가오는 일정은 종료일 기준, 마이페이지 전체 목록은 과거 일정까지 표시합니다.

## 5. 저장 범위와 남은 작업

기본 프로필과 등록한 학교 시험 일정은 Supabase에 저장합니다. **관심 목록·일반 개인 일정은 localStorage이며 현재 로그인·로그아웃·세션 복원에서 초기화됩니다.** 계정별 영구 저장·기기 간 동기화는 미구현입니다.

추가 과제는 프로필 추가 설정 복원, 토큰 자동 갱신, 실제 인기 지표·AI 개인화 추천, 공모전 제출·관리자 검수, 알림 발송입니다. 학교 검색 작업 큐·자동 복구·원문 보관 정책과 `contests` 마이그레이션도 필요합니다. Render 실제 배포 상태는 [배포 문서](deployment.md)를 참고하세요.

## 6. 검증과 문서 관리

- 단위 테스트: `python -m unittest discover -s tests -v`.
- 실제 DB: `python -m tests.verify_academic_database`. 메일 없이 테스트 사용자·행을 생성하고 전체 롤백합니다. 캐시 재사용·중복 방지·일반 사용자 조회·계정 격리·개인 수정·삭제를 확인합니다.
- 브라우저: 개발 환경의 Playwright·Edge로 모바일/PC에서 필터·상세·관심 목록, 로그인·프로필 복원, 홈 2×3, 기간·겹침·주월 경계, 공식 날짜 기본값·수정 보존을 확인했습니다. 일부 화면 테스트는 모의 API를 사용하며 실제 DB 검증과 구분합니다.
- 실제 공모전 DB 37건의 API·목록·상세·관심 저장도 확인했습니다. 이미지 로딩은 원본 서버 조건에 따라 달라집니다.
- 이전 AI 시연의 전체 학교 일정 33건과 현재 시험 전용 범위를 구분합니다. 현재 등록 확인 내역은 중간고사 2건·기말고사 2건입니다.

현행 문서는 README(소개·실행), 이 문서(구현·데이터), deployment(배포) 세 개로 유지합니다. 기능 변경은 해당 절을 갱신하며 기능마다 새 문서를 만들지 않습니다. 과거 기록은 `history/`에 보존하고 현재 구현의 근거로 혼용하지 않습니다.

# 가입·학사일정 자동 조회 및 등록

2026-11-15 구현. PLSAi 화면과 FastAPI 백엔드에서 처리하며 n8n은 사용하지 않습니다.

## 사용자 흐름

1. 프로필 화면에서 이메일·비밀번호로 Supabase에 가입하거나 로그인합니다. 이메일 확인이 필요한 프로젝트는 인증 메일 확인 후 로그인합니다.
2. 학교 공식 명칭·학과·캠퍼스·학년도를 입력하고 저장합니다. 지원 범위는 **학부 공통 학사일정**입니다.
3. 학교·캠퍼스·학년도가 같은 DB 조회 결과가 있으면 재사용합니다. 공백 차이는 정규화하지만 학교 별칭·약어는 자동 병합하지 않습니다.
4. 없으면 Claude의 웹 검색·페이지 가져오기 도구로 공식 `.ac.kr` 자료를 찾아 일정을 추출합니다. 학과·개인정보는 검색 요청에 보내지 않습니다.
5. 정확한 학교·학년도·캠퍼스·날짜 범위·출처 URL·원문 근거를 검증합니다. 공식 페이지에서 읽은 텍스트와 추출 근거가 일치하지 않으면 저장하지 않습니다.
6. 사용자가 출처·날짜를 확인하고 체크한 항목만 개인 캘린더에 등록합니다. 같은 항목을 재등록해도 중복 생성하지 않고 개인 수정 내용을 보존합니다.
7. 다른 사용자도 공유 DB 결과를 먼저 보지만, 각자의 확인·선택을 거쳐 별도의 개인 일정으로 등록합니다.

학교 공통 자료와 사용자 개인 일정은 분리합니다. 개인 수정·삭제는 공통 자료와 다른 사람 일정에 영향을 주지 않습니다. 한 사람의 확인만으로 공통 AI 결과를 기관 검증 사실로 승격하지 않습니다.

## 구성

- `src/academic/discovery.py`: Claude 검색·추출·출처 근거 검증. API 키는 서버에서만 사용합니다.
- `src/academic/routes.py`: 계정 연결, DB 우선 조회, 백그라운드 작업, 선택 등록, 본인 일정 조회·수정·삭제.
- `src/web/js/academic.js`: 가입·학교 입력·진행 상태·출처 검토·선택 등록 화면.
- `academic_calendar_lookups`: 공유 검색 상태와 일정 후보. 브라우저 Data API 직접 접근은 차단하고 인증된 백엔드로 조회합니다.
- `universities` / `academic_events`: 선택 등록 시 학교·공통 원본을 보관합니다. AI 후보는 `unverified` 상태입니다.
- `calendar_events`: RLS로 사용자별 일정 분리. `academic_event_id`로 공유 원본에 연결합니다.

마이그레이션: `supabase/migrations/20261115000100_academic_discovery.sql`, `20261115000200_preserve_shared_academic_cache.sql`. 최초 요청자가 탈퇴해도 학교 공통 캐시는 유지합니다.

## 설정·실행

`.env`에 `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, Supabase 공개 URL·키, DB 연결 정보를 설정합니다. 기본 모델은 `claude-sonnet-4-6`이며 실제 계정에서 지원하는 검색·fetch 지원 모델로 변경할 수 있습니다. Claude 호출에는 API 크레딧과 웹 검색 사용 설정이 필요할 수 있습니다.

```powershell
.\.venv\Scripts\python.exe -m src.web.server
```

이메일·비밀번호는 서버를 거쳐 Supabase Auth에 전달하며 별도 저장하지 않습니다. 액세스 토큰은 브라우저 탭의 sessionStorage에 보관하고 API는 서명을 검증합니다. 세션 갱신은 아직 자동화하지 않아 토큰이 만료되면 다시 로그인해야 합니다. 배포 시 HTTPS를 사용합니다.

## 검증과 한계

- 검증 대상 학교: 동양미래대학교, 학과: 인공지능소프트웨어학과. 테스트용 정보이며 가입 폼의 기본값으로 강제하지 않습니다.
- 실제 Claude 검색으로 동양미래대학교 2026학년도 공통 일정 33개를 추출하고 공식 원문 근거를 검증했습니다. 첫 시연용 공유 캐시에 저장하되 개인 계정에는 자동 등록하지 않습니다.
- 학교별 수업·시험 차이는 추정하지 않습니다. 강의별 중간·기말고사는 공통 학사일정과 다를 수 있습니다.
- 접근이 제한된 사이트·이미지 PDF·근거를 확인할 수 없는 문서는 실패 안내를 표시합니다. 모든 대학을 지원한다고 보장하지 않습니다.
- 결과는 자동 갱신하지 않습니다. 학년도별로 구분하며 일정 변경 시 운영자 재검토·갱신이 필요합니다.
- 작업은 현재 Python 프로세스에서 실행합니다. DB에 상태를 저장하고 20분 이상 중단된 작업은 재요청 시 재시작할 수 있지만 서버 종료 후 자동 복구 워커는 없습니다.
- 같은 학교의 동시 최초 요청은 DB 잠금으로 중복 AI 호출을 막습니다. 신규 검색은 사용자당 1분 간격 제한을 둡니다.
- 개발 테스트는 Claude 응답 모의 테스트, 브라우저 동작 확인, 실제 DB 롤백 검증을 분리합니다. 실제 AI 성공 여부는 키·크레딧과 공식 사이트 접근 상태에 따라 별도 보고합니다.

수동 직접 입력 일정 등 기존 localStorage 기능은 그대로 남아 있습니다. 이번 DB 연결 범위는 확인 후 등록한 학사일정이며, 관심 목록·공모전·전체 개인 일정의 DB 전환은 별도 작업입니다.

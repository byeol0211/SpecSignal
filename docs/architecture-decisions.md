# SpecSignal Architecture Decisions

## 1. 프로젝트 초기 방향

초기에는 다음과 같이 모든 데이터를 사전에 수집하여 자체 데이터베이스를 구축하려고 했다.

- 전국 대학 학사일정을 대학별로 크롤링
- 국가자격 시험정보 수집
- 국가공인 민간자격 시험정보 수집
- 수집된 데이터를 기반으로 자격증 추천 및 알림 제공

초기 구조:

```text
전국 대학 → 대학별 학사일정 크롤링 → 학사일정 DB

국가자격 / 국가공인 민간자격 → API 및 크롤링 → 자격증 DB

두 데이터를 결합 → 추천 알고리즘 → 챗봇 / 알림
```

## 2. 초기 방식의 문제점

### 대학 학사일정

전국 대학의 학사일정을 하나의 크롤러로 수집하기 어렵다.

대학마다 다음 요소가 서로 다르다.

- 홈페이지 구조
- HTML / JavaScript / PDF 등 제공 방식
- 중간고사 / 중간시험 / 학기말시험 등 일정 표현
- 학사일정 페이지 위치와 URL 구조

따라서 전국 대학별 크롤러를 직접 구현하면 데이터 수집에 지나치게 많은 개발 시간이 필요하다고 판단했다.

### 국가공인 민간자격

SQLD, ADsP 등 국가공인 민간자격은 자격정보 목록은 확보할 수 있지만 시험일정을 통합 제공하는 API를 찾기 어렵고, 시행기관별로 시험일정을 별도로 수집해야 한다.

MVP 범위에 포함하면 개발 범위가 지나치게 커지므로 향후 확장 기능으로 남기기로 했다.

## 3. 변경된 데이터 수집 전략

모든 데이터를 사전에 수집하는 방식에서 다음 원칙으로 변경했다.

> 신뢰할 수 있는 정형 데이터는 공식 API를 통해 수집하고,
> 비정형 데이터는 필요한 시점에 검색하여 LLM으로 구조화한다.

### 국가자격

공공데이터 API를 이용한다.

- `15003024`: 국가자격 종목 목록 및 `jmCd`
- `15003003`: 국가자격 종목별 상세정보
- `15074408`: 국가자격 시험일정

`jmCd`를 기준으로 데이터를 결합하여 SpecSignal의 자격증 데이터셋을 구축한다.

흐름:

`15003024 → 15003003 → 15074408 → 정규화/JOIN → 자격증 DB`

## 4. 대학 학사일정 수집 전략 변경

기존:

`전국 대학 → 대학별 크롤러 → 학사일정 DB`

변경:

`사용자 학교명 입력 → 기존 DB 확인 → 없으면 웹 검색 → 대학 공식 출처 확인 → 페이지 내용 확보 → LLM Structured Extraction → Validation → 사용자 확인 → DB 저장`

예를 들어 사용자가 "동양미래대학교"를 입력하면 해당 연도의 공식 학사일정을 검색하고, 공식 대학 출처의 내용을 기반으로 LLM이 다음과 같은 공통 형식으로 변환한다.

- SEMESTER_START
- MIDTERM
- FINAL
- SEMESTER_END
- VACATION

한 번 검증된 대학/연도의 일정은 DB에 캐싱하여 같은 데이터를 반복 검색하거나 LLM으로 처리하지 않도록 한다.

## 5. 정확도 보완

LLM의 결과를 바로 데이터베이스에 저장하지 않는다.

다음 과정을 거친다.

`공식 출처 확인 → LLM 추출 → Schema Validation → 사용자 확인/수정 → 저장`

또한 다음과 같은 상황에서는 추측하지 않고 실패 또는 확인 필요 상태로 처리한다.

- 다른 연도의 학사일정
- 대학원 등 다른 교육과정의 일정
- 날짜가 명확하지 않은 경우
- 필요한 일정이 원문에 존재하지 않는 경우

사용자가 자동으로 검색된 일정을 수정할 수 있도록 한다.

## 6. 직접 입력 Fallback

자동 검색에 실패하거나 실제 시험 일정이 학과/교수별로 다른 경우를 위해 사용자가 자연어로 직접 일정을 입력할 수 있도록 한다.

예:

> "중간고사 4월 20일부터 24일까지, 기말고사는 6월 15일부터 일주일"

LLM이 이를 동일한 학사일정 스키마로 구조화한다.

## 7. 현재 MVP 범위

포함:

- 국가자격 종목 데이터 수집
- 국가자격 시험일정 수집
- 학교명 기반 대학 공식 학사일정 검색
- LLM 기반 학사일정 구조화
- 사용자 직접 일정 입력
- 학사일정과 자격시험 일정 결합
- 개인화 추천
- 챗봇
- 일정 알림

향후 확장:

- 국가공인 민간자격
- 공모전 데이터
- 대학 학사일정 자동 갱신 범위 확대

## 8. 현재 핵심 아키텍처 원칙

SpecSignal은 모든 정보를 LLM으로 처리하지 않는다.

구조화된 공공데이터는 일반적인 데이터 파이프라인으로 처리하고, 대학 학사일정처럼 형식이 일정하지 않은 비정형 데이터의 해석과 구조화에 LLM을 사용한다.

이를 통해 데이터의 신뢰성과 개발 범위를 관리하면서도 다양한 대학의 학사일정 형식에 대응할 수 있는 구조를 목표로 한다.
